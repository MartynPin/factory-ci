# factory-ci

Первый контур фабрики: **определения гейтов**. Агент сюда не пишет — ни в один
файл, ни при каких условиях.

Здесь лежит код, который решает, пройдена работа или нет. Если бы агент мог его
менять, проверки перестали бы быть проверками.

---

## Что внутри

| Путь | Что |
|---|---|
| `.github/workflows/gates.yml` | Reusable workflow: предполёт, гейты, проверки диффа, вердикт |
| `.github/workflows/merge-bot.yml` | Мердж по метке `approved` — копируется в продуктовый репозиторий |
| `.github/workflows/verify-protection.yml` | Еженедельная сверка фактической защиты с ожидаемой |
| `setup/bootstrap.sh` | Применяет модель прав к продуктовому репозиторию |
| `setup/verify.sh` | Проверяет фактическое состояние и печатает расхождения |
| `ACCESS-MODEL.md` | **Модель прав и секретов — читать первым** |

---

## Как подключить продуктовый репозиторий

```bash
setup/bootstrap.sh OWNER/my-app          # --dry-run покажет, что будет сделано
setup/verify.sh    OWNER/my-app          # убедиться, что применилось
```

Затем в `.github/workflows/ci.yml` продуктового репозитория заменить `@main` на
полный 40-символьный SHA коммита этого репозитория.

## Три вещи, которые здесь важнее остальных

**1. Обязательная проверка ровно одна — `verdict`.** GitHub засчитывает
`skipped` как успех: джоба, пропущенная по условию `if:`, для branch protection
неотличима от пройденной. Поэтому в настройках ветки перечислена одна джоба,
которая запускается всегда и сама собирает результаты остальных. Список гейтов
можно менять, не трогая защиту ветки.

**2. `env_fail` — не «красный».** У GitHub нет третьего статуса, поэтому отказ
окружения кодируется провалом `verdict` **плюс меткой `env_fail`** на PR. PR
блокируется в обоих случаях — сломанное окружение не повод мерджить, — но метка
отличает «агент не справился» от «инструмент сломан», и именно она решает,
запускать ли ретрай. Основание: `factory-knowledge/lessons/L-001`.

**3. Ослабление проверок разрешено, но обязано быть объяснено.** Гейт не
запрещает правку конфигурации проверок: легитимное ослабление синтаксически
неотличимо от нелегитимного, и запрет заблокировал бы полезное вместе с
вредным. Вместо запрета — требование блока `## Ослабление проверок` в описании
PR и отдельный вердикт ревьюера по нему. Основание:
`factory-knowledge/lessons/L-002`.

## Почему проверки диффа написаны прямо в workflow

Reusable workflow исполняется в контексте **вызывающего** репозитория: checkout
приносит код продуктового проекта, а файлы `factory-ci` там недоступны. Второй
checkout приватного `factory-ci` потребовал бы токена — ровно того секрета,
которого у джоб гейтов быть не должно.

Поэтому код проверок диффа встроен в `gates.yml`. Это некрасиво и это
осознанно: единственная альтернатива хуже.

## Чего здесь нет

- **Учёта стоимости.** Агент работает локально, вне Actions; Actions считает
  только минуты. Два потолка без общего агрегата — открытая находка A-15.
- **Гейтов безопасности** (gitleaks, Semgrep, `npm audit` против базовой линии).
  Добавляются при первом реальном продукте, вместе с ролью безопасности.
- **Lighthouse.** Добавляется вместе с шаблоном `ad-landing`.
